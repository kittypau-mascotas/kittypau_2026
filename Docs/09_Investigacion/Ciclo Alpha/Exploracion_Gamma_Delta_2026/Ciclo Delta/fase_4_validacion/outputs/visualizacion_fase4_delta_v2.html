¿Qué curvas estamos buscando detectar?

El sensor mide el peso del tazón cada ~30 segundos. Cada patrón de variación tiene un significado físico.
Evento SERVIDO
Curva: subida aguda y rápida.
delta_w > +5g en una sola lectura. Ocurre cuando la dueña llena el tazón. Duración típica: 30–300 seg. Cluster 0 de K-Means.
ALIMENTACIÓN
Curva: descenso gradual sostenido.
delta_w negativo pequeño y constante. Bandida come. Puede durar 5–30 min. Cluster 1, parte baja.
REPOSO
Curva: línea plana con ruido mínimo.
|delta_w| < 2g, peso estable. El tazón no se usa. Cluster 1, mayor parte del tiempo (97%).
ANOMALÍA
Curva: saltos eráticos o inconsistentes.
Puede ser hardware (reloj inválido), comportamiento nocturno inusual, o lecturas imposibles. Detectadas por IF y LOF.

Por qué Unsupervised (Ciclo Delta)

Gamma requería etiquetas humanas. Delta responde a: ¿puede la máquina encontrar estos patrones SOLA, sin decirle qué buscar? Si los clusters son coherentes con las etiquetas de Gamma → validación cruzada de que el modelo supervisado aprendió algo real.

18 features → espacio vectorial

El modelo no ve el tiempo ni el peso crudo directamente. Ve 18 features derivadas: delta_w, rolling_std_5/10/30, net_weight, hour_sin/cos, plateau_duration, clock_invalid, etc. El clustering opera en ese espacio.

Resultado clave

K-Means con k=2 obtuvo Silhouette=0.816 (excelente). Cluster 0 = servido (50.1% pureza), Cluster 1 = todo lo demás. Con el gráfico de peso histórico abajo puedes verificar qué identificó cada modelo.

Isolation Forest — Red de detección amplia

Qué hace

Construye árboles de decisión aleatorios. Una lectura es anómala si se aísla con pocos cortes del árbol (= es "rara" en el espacio de 18 features).

Curva que detecta

Cualquier reading estadísticamente inusual: valores extremos de peso, delta_w imposible, clock_invalid activado, combinaciones extrañas de features.

Qué ves en el gráfico

Puntos naranjas = muestra de 600 de los 6,709 flaggeados por IF. Muchos coinciden con períodos de ruido visible en la curva de peso.

Limitación

Alto recall pero baja precisión. No distingue si la anomalía es falla de hardware o comportamiento real interesante. Muchos falsos positivos.

Local Outlier Factor (LOF) — Detector de densidad local

Qué hace

Compara la densidad local de cada punto con sus k vecinos más cercanos. Si tu densidad es mucho menor que la de tus vecinos → eres un outlier local.

Curva que detecta

Lecturas que forman "islas" aisladas en el espacio de features. Detecta outliers locales que IF puede perder (clusters de densidad variable).

Qué ves en el gráfico

Puntos amarillos = muestra de 600 de los 6,709 flaggeados por LOF. Aunque la cantidad es idéntica a IF, los puntos individuales son distintos.

Relación con IF

Solo 676 de 6,709 anomalías coinciden con IF (10% de solapamiento). LOF e IF tienen perspectivas complementarias de la "rareza" de un punto.

Consenso IF ∩ LOF — Anomalías de alta confianza

Qué hace

Una lectura es anomalía consenso solo si AMBOS detectores la marcaron. El filtro de intersección reduce los falsos positivos: 6,709 → 676.

3 tipos en el gráfico

• Rojo = Tipo H: clock_invalid ≥ 0.75 → dato no confiable de hardware
• Amarillo = Tipo C: anomalía en horario activo (6–22h)
• Morado = Tipo U: nocturna (22:00–06:00)

Por qué importa el tipo

H: Excluir esas ventanas del entrenamiento de Gamma.
C: Revisar manualmente, pueden ser sesiones nuevas no capturadas.
U: Bandida comiendo de noche — patrón nuevo.

Limitación

Algoritmos en detalle — Métricas comparativas

Resultados numéricos de cada fase del Ciclo Delta.
🏆

Ganador: K-Means k=2 — Silhouette 0.816

Separación binaria clara entre subidas de peso (servido) y el resto. Los tres algoritmos alternativos (DBSCAN, HDBSCAN, GMM) confirmaron la estructura pero con granularidad excesiva o métricas peores.

K-Means: Silhouette por k (k=2→7)
Silhouette: cuán separados y compactos son los clusters (0–1, mayor=mejor). k=2 gana claramente. La línea punteada marca el umbral mínimo de utilidad (≥0.25).
Comparación de algoritmos de clustering
K-Means (k=2) domina. DBSCAN y HDBSCAN generaron 1,322 y 1,868 clusters — sobreajuste inutilizable para detección de servido.
DBSCAN: Silhouette vs eps
eps controla el radio de vecindad. eps muy pequeño (0.3) = más clusters, mejor Silhouette pero 1,322 micro-clusters. eps grande = colapsa todo en un sólo cluster = Silhouette negativo.
GMM: curva BIC (n=2→7)
BIC (menor=mejor) sigue bajando hasta n=7. En GMM no hay un "codo" claro — más componentes siempre mejoran BIC, lo que hace la selección poco práctica para este dataset.
Volumen de anomalías por detector (escala log)
IF y LOF detectan exactamente 5% cada uno (configurado por contamination=0.05), pero solo el 10% se solapan. El consenso (676) es el subconjunto más confiable.
Anomalías consenso por tipo
H=hardware (reloj del sensor con error), C=conductual en horario activo (6–22h), U=nocturna (22–06h). Cada tipo requiere una acción distinta.
Anomalías consenso por mes
Distribución temporal: Abr=255, May=196, Jun=225. La caída en Mayo coincide con período post-reparación del cargador documentado en 06_AUDITORIA_SIN_CARGADOR.md.
ARI y NMI vs umbrales mínimos esperados
ARI=0.159 (umbral mínimo 0.20). El bajo ARI es esperado: K-Means genera 2 clusters vs 4 clases en Gamma. No es un fallo — es una diferencia estructural de granularidad.
Pureza de clusters vs etiquetas Gamma (cross-check D04)
Cluster 0 = dominado por "servido" (50.1%). Cluster 1 = dominado por "alimentación" (68.6%). Confirma que los clusters capturan dinámicas semánticamente coherentes sin haber visto las etiquetas.

¿Para qué sirve cada modelo?

Matriz de decisión: objetivo → mejor herramienta.
Objetivo
Detectar sesiones de servido sin etiquetas
Usar K-Means Cluster 0. Silhouette 0.816 = separación muy clara. Pureza 50.1% de "servido" validada por Gamma sin haber visto esas etiquetas. Base para pseudo-etiquetado en Ciclo Epsilon.
Objetivo
Identificar datos corruptos / hardware failure
Usar Consenso Tipo H (338 eventos con clock_invalid ≥ 0.75). Estos períodos se excluyen del dataset de entrenamiento de Gamma. Coincide con la auditoría del cargador documentada.
Objetivo
Encontrar comportamiento nuevo/atípico de Bandida
Usar Consenso Tipo C y Tipo U (338 eventos). C = durante horas activas, puede ser sesión nueva. U = nocturna, patrón no documentado en Gamma (Bandida comiendo de madrugada).
Objetivo
Expandir el dataset de entrenamiento de Gamma
Usar Candidatos Servido (D05). Los 2 nuevos de Jun 01–02 se revisan con app_anotacion_gamma.py. No se resonó entrenamiento solo por 2 casos (umbral era ≥10).
Objetivo
Bootstrapping para Ciclo Epsilon (semi-supervisado)
K-Means como pseudo-etiquetador: Cluster 0 → candidato servido, Cluster 1 → alimentación/reposo. Permite entrenar con 134K+ puntos sin anotación humana completa.
Objetivo
Validar que Gamma aprendió algo real
ARI=0.159 es validación positiva, no fallo. K-Means (sin etiquetas) capturó el patrón de servido con 50.1% de pureza. Confirma que Gamma detectó un fenómeno físico real.
Pendiente: Instalar Visual C++ Redistributable 2022 x64 para resolver el error PyTorch/c10.dll. Con el Autoencoder funcionando (3/3 detectores), el consenso de 676 se reducirá y los tipos C/U tendrán menor contaminación de hardware.
